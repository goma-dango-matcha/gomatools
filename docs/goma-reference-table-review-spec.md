# ゴマ早見表 実装レビュー仕様書 Version1.0

| 管理項目 | 内容 |
| --- | --- |
| 文書種別 | 共通仕様書 |
| 対象 | ゴマ早見表 全ページ |
| 適用範囲 | 新規実装・改修・リファクタリング |
| 状態 | 正式版 |
| 公開区分 | 内部資料 |
| Commit・Push | 行わない |

---

## 1. 目的

本仕様書は、ゴマ早見表シリーズの品質を一定水準以上で維持するためのレビュー基準を定義する。

新規ページ、既存ページの改修、UI改善、SEO改善などを実施した場合は、本仕様書に従ってレビューを実施する。

レビューでは次を総合的に確認する。

- 情報の正確性
- UI品質
- ブランド整合性
- SEO
- 保守性
- 回遊性

---

## 2. レビュー実施タイミング

以下のタイミングで実施する。

- 新規ページ実装後
- 大きな仕様変更後
- SEO変更後
- デザイン変更後
- JavaScript変更後
- CSS変更後
- 共通コンポーネント変更後
- 公開前最終確認

軽微な文章修正のみの場合は必要に応じて省略できる。

---

## 3. レビュー対象

対象例：

- HTML
- CSS
- JavaScript
- JSON-LD
- `sitemap.xml`
- `robots.txt`
- metadata
- ゴマ早見表一覧
- 関連リンク
- 候補台帳
- ロードマップ
- `spec-index.md`
- 引き継ぎメモ

---

## 4. データレビュー

必ず確認する。

### 正確性

- 数値
- 年月
- 名称
- 規格
- 単位
- URL
- 出典

### 情報源

一次情報を使用していること。推測は禁止する。

### 重複

同じ情報を複数箇所で正本として管理していないこと。

---

## 5. UIレビュー

確認項目：

- レイアウト崩れ
- 余白
- タイトル
- `h1`
- `h2`
- テーブル
- カード
- CTA
- ボタン
- アイコン
- 配色
- ブランドカラー
- ゴマワンポイント

既存早見表との統一感を維持する。

---

## 6. スマートフォンレビュー

最低確認幅：

- 320px
- 360px
- 375px
- 390px

確認内容：

- 横スクロールなし
- タップしやすい
- テーブル崩れなし
- カード崩れなし
- CTA崩れなし
- パンくず正常
- フッター正常

---

## 7. PCレビュー

確認幅：

- 1024px
- 1280px
- 1440px

確認内容：

- 横幅
- テーブル
- CTA
- 行間
- 可読性
- フッター
- サイド余白

---

## 8. SEOレビュー

確認項目：

- `title`
- `meta description`
- canonical
- robots
- sitemap
- OGP
- `h1`

`h1`は1つとし、`h2`以降の階層が正しいこと。

---

## 9. 構造化データレビュー

確認項目：

- `WebPage`
- `BreadcrumbList`
- `ItemList`
- `FAQPage`

画面表示と一致していること。非表示データは禁止する。

---

## 10. 回遊性レビュー

確認項目：

- 関連ページ
- 関連ツール
- ゴマ早見表一覧
- パンくず
- ホーム導線

必要な相互リンクがあること。不要なリンクや未公開ページへのリンクは追加しない。

---

## 11. JavaScriptレビュー

確認項目：

- Consoleエラーなし
- Warningなし
- 二重初期化なし
- 二重イベントなし
- 共通JavaScriptを破壊していない

ページ固有JavaScriptは最小限とする。

---

## 12. CSSレビュー

確認項目：

- 未使用CSSなし
- `!important`の乱用なし
- 命名統一
- 共通クラス再利用
- 既存ページへ影響なし

---

## 13. アクセシビリティレビュー

確認項目：

- `alt`
- `caption`
- `scope`
- `aria`
- キーボード操作
- フォーカス表示
- 色だけで区別しない

---

## 14. パフォーマンスレビュー

確認項目：

- 不要画像なし
- 不要JavaScriptなし
- 不要CSSなし
- 外部ライブラリ追加なし

静的ページを基本とする。

---

## 15. ブランドレビュー

ブランド仕様書と一致していること。

確認項目：

- トーン
- ゴマワンポイント
- CTA
- 配色
- タイトル
- シリーズ感

---

## 16. 管理文書レビュー

必要に応じて確認する。

- 候補台帳
- ロードマップ
- `spec-index.md`
- 引き継ぎメモ
- sitemap

更新漏れがないこと。

---

## 17. レビュー報告フォーマット

レビュー完了後は必ず次の形式で報告する。

```text
## 変更ファイル

## レビュー結果

### JavaScript

### PC表示

### 管理文書

```

## 18. NG例

レビューでは以下を見逃さない。

- Consoleエラー
- 横スクロール
- `title`未設定
- `h1`重複
- canonical不一致
- sitemap未更新
- 構造化データ不一致
- 未公開ページリンク
- URL切れ
- 推測データ
- 古い情報源
- 二重CTA
- 二重リンク
- CSS重複
- JavaScript重複

---

## 19. 完了条件

以下をすべて満たした場合のみレビュー完了とする。

- データが正確
- UI正常
- SEO正常
- 構造化データ正常
- 回遊性正常
- スマートフォン表示正常
- PC表示正常
- Consoleエラーなし
- リンク切れなし
- 管理文書更新済み
- ブランド仕様に準拠
- 重大な指摘事項なし

---

## 20. Codexへのレビュー依頼文

実装内容を本仕様書に従ってレビューする。

レビューでは次を必ず確認する。

- データの正確性
- 情報源
- UI
- スマートフォン表示
- PC表示
- SEO
- 構造化データ
- 回遊性
- JavaScript
- CSS
- アクセシビリティ
- ブランド整合性
- 管理文書
- リンク切れ
- Consoleエラー

レビュー後は次を報告する。

- 変更ファイル
- レビュー結果
- 問題点
- 修正内容
- 要確認事項

重大な問題がある場合は優先度順に整理する。問題がない場合も、確認した内容を省略せず報告する。

Commit・Pushは行わない。
